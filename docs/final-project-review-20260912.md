# 决赛前整项目复核（持续更新）

目标是检查代码、实际运行、复现入口、前端和比赛材料的一致性；不能仅凭原有绿色测试宣布整项目审查完成。所有构建、测试、浏览器与故障验证在 10.10.10.202 Docker 中执行，保留原 8 个演示案件、执行记录和账务。

## 本轮有证据的发现

| 发现 | 影响 | 处理及验证 |
| --- | --- | --- |
| 只有旧核心表时，应用 Schema 检查仍成功 | 全量部署遗漏资金迁移后，直到网关初始化或资金功能才失败 | 隔离 PG 复现 `RuntimeError not raised`；迁移/应用共用清单，检查全部必要表；缺表拒绝启动，重复迁移保留审计历史 |
| `deploy_demo.sh --full` 只运行 `001_core.sql`，未组合观测覆盖层 | 新部署缺少资金表，更新 API 会丢失 OTel/Grafana 配置 | 改为构建后短时容器调用完整迁移入口；完整部署加入观测和共享看板；无法读取活动运行时拒绝部署 |
| 常用 PG 目标只跑原有 2 项，release 不要求 PG | 资金恢复和真实数据库迁移可被跳过 | `verify-release` 强制 PG 门禁；22 项包含恢复、迁移与既有集成；新增一次性 Docker 验证入口，独立网络且不挂载生产卷 |
| Vite / PostCSS 等存在 5 项 npm 审计问题（4 high、1 moderate） | 构建工具仍携带已知漏洞 | Vite 更新为 6.4.3，修复传递依赖，npm 审计为 0；完整门禁、构建和浏览器验证通过 |
| README、部署/依赖文档与现状不符 | 容易把读取偏差、旧任务数、无 MCP、标准库边界或历史 CI 当作当前事实 | 更新当前文档，保留历史证据；明确资金结果未知恢复、Grafana、依赖和 202 Docker 入口 |

0.5.2 已部署至 202；发布镜像的 Debian/Python 可修复 HIGH/CRITICAL 扫描为 0，原 8 个案件、执行记录、9 条 ledger 和 261 行审计链前后一致。阶段验收见 [project-audit-20260912](evidence/project-audit-20260912/README.md)。这些结果证明本轮修复，不代表整项目复核已经结束。
