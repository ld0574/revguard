# 资金结果未知时的恢复协议

状态：已实现；202 Docker 隔离环境完成 PostgreSQL 恢复合同测试。适用范围是 RevGuard 自管模拟台账，不表示已接入外部 ERP 或支付系统。

## 写入与补偿

一次业务调整的两个组件通过一个 LedgerAdjustSkill 批次提交；对应冲销通过一个 LedgerReverseSkill 批次提交。每个原始分录保留，冲销新增带 `reversal_of` 的反向分录。同一原始分录最多有一条全额冲销，禁止对冲销记录再次冲销。

`money_operations` 先提交操作意图，包含稳定 ID、案件、订单通道、参数 hash 和 generation。随后在同一数据库事务中提交分录、幂等结果、execution 投影、必要审计和本地 outbox 事件。整个批次要么提交，要么无资金效果。数据库审计失败也必须撤销资金事务。

资金调用超时或连接中断只调用一次，进入 `RESULT_UNKNOWN`，案件进入 `RECOVERY_REQUIRED`。相关订单通道冻结；换任务号或幂等键不能绕过未确认意图。只读工具仍可按原策略有限重试。

## 恢复入口

审批人通过原有身份验证为 `RESUME` 签发短期证明，再调用 `/api/v1/cases/{case_id}/team/resume`。普通 API 操作者密钥不能替代此人审。

恢复首先在唯一可写主库上取得与资金执行相同的事务锁。已提交操作重建投影；未提交意图推进 generation，阻止暂停在意图与执行之间的旧请求继续写入。只有对账完成后才续发剩余授权并继续原操作。查询原结果不会再次消费授权金额。

`GET /api/v1/cases/{case_id}/money-operations` 提供受保护的只读操作查询。`money_outbox` 当前是本地事务事件记录，尚未实现外部系统的可靠投递器。

## 数据库故障与备份恢复

数据库不能写入时，不宣称新的冻结状态已落库。资金请求之前已提交的 `PREPARED` 意图仍作为恢复门禁，日志与 OTLP 导出独立于业务库；Prometheus 与 Blackbox 从外部告警。

日常重启仅在数据库历史完整、唯一写主成立的条件下使用上述对账。**从备份或 PITR 恢复之前，必须在所有写实例上设置 `REVGUARD_MONEY_RECOVERY_LOCK=true`，再启动恢复后的服务。** 此开关同时阻断资金准备、执行和恢复入口，放在恢复库之外，不能从旧备份中的“查无记录”自动解除。

运维确认恢复窗口、唯一写主、旧进程隔离及所有可能的外部资金效果后，留存对账证据，才可移除该开关并重启写实例。当前系统不会自动识别任意外部恢复操作；绕过此运维步骤不在保证范围内。未验收真实主备切换、PITR 或外部 ERP 恢复，不将容器重启描述为高可用。

## 核验与演示

首次读取差异需再次从自管权威台账确认，短暂读取偏差不会立即冲销。核验使用本次执行的不可变基线和相关分录，排除执行后进入的其他合法交易。

Case8 故障测试改为真实修改合成写入金额；正常写入与读取偏差是不同测试。故障分支当前为 18 个实际任务；正常分支任务数按接口结果展示。原复赛录制中的 17/17、20/20 是历史运行记录，不覆盖成新数字。

所有构建、测试、服务和故障演练均在 `10.10.10.202` 的 Docker 中执行。本地只编辑、同步文件；不得对原演示容器或数据注入故障。
