## 1. 统一口径

- 订单、合同、政策、回款和台账是合成业务数据；模拟台账不连接公司生产资金。
- AgentTeams/Matrix、职能 Worker、Higress MCP 调用、服务端状态流、审批身份校验、
  执行、独立验证、冲销和审计均实际运行。
- 1 个编排 Agent + 9 个职能 Worker。业务流程由确定性状态机裁决，不能说 Manager
  自主制定了财务政策，也不能把模型执行耗时等同于底层本地 Skill 耗时。
- 完整部署使用 9 个 actor-scoped Higress MCP Server。职能 Worker 只持 consumer token，
  后端 key 在 Higress；本地 stdio 仅为测试环境。
- 人工审批使用独立网页的 Matrix 账号验证。120 秒动作证明绑定案件、审批单与决定；
  批准后签发 15 分钟执行能力。不是企业 SSO/MFA，也不是 AgentTeams 原生 Approval Gate。
- 自动化验收调用只是测试身份认证和执行链路；正式视频必须由组员本人完成登录与点击，
  不把脚本测试称为“真人在场”。

> 我们做的是企业结算异常的多智能体治理。

字幕：1 KES 偏差 → 反向冲销 → 回滚复核通过。

### 00:20–00:45｜说明数据边界

画面：在录制专用库点击“重新准备”，确认 CREATED；案件摘要与披露同框。
注意：重新准备会重置全部演示案件，不在别人正在运行时点击。

旁白：

> 由于企业生产数据未获授权，本演示使用按业务规则构造的合成订单、合同、政策和财务台账。
> 数据和外部系统适配器是模拟的；调查、协作、权限、验证、回滚和审计是真实运行的。

### 00:45–01:25｜真实协作与 MCP 隔离

画面：点击“启动多智能体调查”；留在“决策依据”，在右侧“多智能体协同任务账本”展开任务，
依次展示受理、取证和政策三个不同 Worker 的输入、输出、任务号、消息号、回执及“MCP 网关”。
补 5–8 秒真实 Matrix 房间录屏，关联同一 task/request/receipt，不用架构图替代运行证据。

旁白：

> 一个编排 Agent 与九个职能 Worker 分工处理案件。任务绑定案件版本、执行者和输入快照，
> 只有服务端持久化的阶段结果才能推进流程。这里的输入、输出与回执，能够和 Matrix 消息相互核对。
> 职能 Worker 通过 Higress MCP 网关调用自己的 Skill；九个 Server 按身份分别授权，
> Worker 不持有后端凭证，也不能用聊天里的“完成了”代替真实结果。

字幕：Matrix 协作｜MCP 按角色授权｜StageResult 驱动状态。

### 01:25–02:05｜取证与政策回溯

画面：“决策依据”中的证据包和政策时间线；8 项证据、Q1/Q2 排除、Q3 采用。
如这次运行存在预设工具失败，再展示对应 ERROR 与后续成功记录；没有就不说“本次重试”。

旁白：

> 取证阶段并行访问七路独立输入，政策查询再按合同依赖继续，最终形成八项强证据。
> 每项证据都保留来源与回执。政策智能体按订单发生时点回溯版本，
> 排除不覆盖业务日期的 Q1、Q2，采用 Q3 和当时生效的合作等级。
> 工具不可用时，系统保留失败记录并按策略重试，不补造证据。

### 02:05–02:35｜金额可复算

画面：计算账本两行公式及差异；计算账本下方的不可篡改审计详情。

旁白：

> 金额不由语言模型猜测。确定性规则内核计算销售佣金二万七千 KES，
> 回款佣金五千四百，合计三万二千四百。对比原台账一万八千，
> 销售佣金少算九千，回款佣金漏记五千四百，总差额一万四千四百 KES。

字幕：180,000 × 15% = 27,000；180,000 × 3% = 5,400。

### 02:35–03:20｜真正的审批边界

画面：WAITING_FOR_APPROVAL 静止至少 3 秒。
点击“批准 14,400.00 KES”（以当前按钮金额为准），打开身份验证弹窗。由组员本人登录演示 Matrix 账号 `admin`；
密码输入过程不录或遮挡，不拍密码管理器。验证后拍案件/审批单/动作绑定，再亲自提交。
切“权限边界”拍身份 subject、认证方式、动作证明指纹、两项额度。

旁白：

> 风险智能体把案件定为 L2，流程在这里真正暂停。Agent 没有审批工具，也没有审批人的凭证。
> 审批人在独立页面登录 AgentTeams Matrix，后端验证账号和白名单，
> 签发两分钟有效、只绑定当前案件与决定的动作证明。
> 批准以后，执行能力还会进一步绑定币种、总额和逐组件额度，有效期十五分钟。
> 一个普通静态 key，或者 Agent 自称“已经批准”，都不能通过。

字幕：带外账号验证 → 120 秒动作证明 → 15 分钟受限执行能力。

### 03:20–04:15｜执行、验证失败与回滚

画面：提交后后台执行，页面轮询真实状态；录到执行、独立验证、冲销、复核。
等待可加速，必须标注“等待过程加速”；不得重排状态或拼出不存在的实时动画。

旁白：

> 审批接口受理后，后台继续调度执行 Worker，分别提交五千四百和九千 KES 的调整。
> 验证 Worker 使用不同身份重新查询台账，不复用执行者的回执。
> 故障演练让首次验证读数多出一 KES，因此验证失败。
> 系统反向冲销两项调整，再次独立查询，确认余额恢复到一万八千 KES。
> 最终保留 ROLLED_BACK，回滚后验证通过，而不是把这次资金写入标成成功。

字幕：执行者 ≠ 验证者｜32,401 − 32,400 = 1｜恢复至 18,000。

### 04:15–04:50｜审计和失败定位

画面：“决策依据”展开任务输入输出，再切“执行与审计”展示 AGENT 秒级耗时、Skill/Tool 实测耗时。
再拍“决策依据”计算账本下的不可篡改审计详情、审批/执行/验证/回滚事件与导出报告。

旁白：

> 每次协作、Skill 调用、审批和冲销都能沿案件、任务、请求与回执反查。
> Agent 阶段耗时包含模型与通信等待，底层确定性 Skill 可能只需不到一毫秒，两者不能混淆。
> 出错时保留具体阶段和错误；进程中断后需要重新授权，续跑用幂等键跳过已经完成的写入。
> 审计链记录谁批准、改了什么，以及如何恢复。

字幕：真实耗时｜真实失败｜身份可归因｜结果可追溯。

## 4. 录制操作顺序

1. 在独立演示库完成一次 0008 全链路预演；先录最终态钩子。
2. 确认没有别的组员运行案件，再点“重新准备”（会清空全部演示运行记录）。
3. 启动 0008 调查，等待 WAITING_FOR_APPROVAL；不要重复点击。
4. 录证据、政策、账本、任务输入输出和 Matrix 房间。
5. 由组员完成账号验证和审批。不要使用自动化验收脚本代替这个镜头。
6. 等待 ROLLED_BACK 且回滚后验证通过，再录最终流水线、审计和报告。
7. 录价值模拟及工程证据。保留无剪辑完整原片，成片可剪等待但不能篡改顺序。
8. 核对公开仓库版本、稿子和画面。账号授权错误或模型限额应先解决再录，不能隐藏错误伪装成功。
