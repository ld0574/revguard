# 复赛反馈核查：隔离故障复现

日期：2026-09-11。这里只复现当前恢复协议的缺口，不是整改后验收。

在`revguard/`目录执行：

```bash
.venv/bin/python docs/evidence/finals-review-20260911/probe_recovery_gap.py
```

脚本复用现有MCP本地参考链路和Golden Case8，在临时目录创建SQLite、模拟网关和报告；不访问AgentTeams服务器、真实财务系统或PolarDB。调查结束后的审批通过测试代码模拟，不是真人审批证据。

第一个探针在业务冲销已经发生、保存execution记录时注入一次`sqlite3.OperationalError`，随后直接检查权威模拟账务和本地执行记录，并调用恢复端点使用的同一令牌续签工具及相同幂等键重发路径。它复现持久化边界，不等价于真实数据库单点故障或完整API恢复端点验收。

第二个探针让通用工具调用层对资金工具收到带`retryable=true`的TIMEOUT，观察是否在未查询操作结果的情况下重复调用。该探针模拟响应，不会实际扣款。

结果保存于`recovery-probe.json`。断言确认的是本轮发现的旧行为：案件状态滞后、令牌续签冲突、相同key冲突、超时三次调用；将来整改后应以新的安全行为测试替代，不能把本脚本纳入“保持现有行为”的发布门禁。
