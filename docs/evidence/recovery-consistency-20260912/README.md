# 人工恢复事务与旧 Worker 隔离验收（2026-09-12）

本批次为 RevGuard 0.5.7，所有构建、测试、服务、故障及浏览器检查均在 10.10.10.202 Docker 中完成。生产环境不注入故障、不重置案件。

| 原版及复核中已复现的问题 | 修正及证据 |
| --- | --- |
| Worker 已领取任务但停在调用工具之前，人工恢复后仍可继续入账 | Skill 执行绑定 task_id、attempt 和案件快照；在工具调用、资金意图和实际效果的数据库事务内检查有效领取；恢复取消旧任务，迟到的 Worker 被拒绝 |
| 恢复的对账、解冻、续签、案件状态和排队分开提交 | 取消旧任务、资金对账、能力续签、投影、解冻、状态、排队和恢复审计一次提交；拒绝案件写入或末尾审计失败时全部回滚 |
| 旧后台任务迟到的异常把新运行重新标成待恢复 | 恢复代次纳入案件业务快照；后台失败写入在同一事务核对代次与录制批次，过期失败不冻结新运行 |
| 多项回滚续签可能只保存前一项，后续对账又覆盖新凭证 | 所有续签同一事务，第二项失败时保留全部原凭证；新凭证同时保存在权威资金状态和执行投影，对账后仍一致 |
| 恢复已提交但后台任务创建失败，不能立即重试恢复 | 持久化可恢复的启动失败状态；重新确认后可再次恢复，保留已授权动作及审计 |
| 从 EXECUTING 恢复时跳过 PermissionCheckSkill | 有待写入分项时重新检查写入授权；全部已提交时由主库验证分项金额、币种与回执后仅允许继续核验，无剩余额度也无需新增能力凭证；浏览器发现的遗漏保存在 `permission-gap-before.json` |

`reproduced.log` 为修改前 8 项失败（SQLite/PG 各 4 项），包含真实旧 Worker 迟到入账。最终 `permission-contracts.log` 的 41 项恢复/资金契约全部通过，包含本批次新增的 24 项双后端契约；其中包括独立连接上的并发恢复、资金意图与效果之间的恢复隔离，以及恢复后真实 MCP 闭环，旧任务 CANCELLED、不残留 RUNNING。

最终 `release.log` / `release-exit.txt`：**291 项唯一测试**，主套件 220 项通过，71 项 PostgreSQL 测试另行全部通过，显示覆盖率 **91%**，确定性评测 105/105。Ruff、生成契约检查、pip-audit、Bandit 通过。前端源代码沿用已验收版本，不把历史前端单元测试计为本批次新测试。

浏览器使用独立 PostgreSQL 数据库和真实 RevGuard API/MCP 链：预置一个中断的 RUNNING 任务与资金通道冻结，数据库触发器拒绝恢复案件写入；页面显示恢复未确认，案件、审批、任务、资金状态与恢复事务审计均保持原状。身份验证成功的 `HUMAN_IDENTITY_VERIFIED` 是独立审计，保留并从业务快照比较中排除。解除故障后在同一页面再次人审，最终 CLOSED，16 项成功 StageTask、1 项旧任务 CANCELLED、两条执行记录，手机宽度无外层溢出。

**身份边界：**浏览器身份服务使用隔离 Matrix HTTP 契约夹具，不冒充生产 AgentTeams 或真实企业身份系统的重新验收。复验脚本和业务快照摘要保存在本目录，故障脚本只能用于一次性隔离环境。

生产仅更新 API 镜像。`deployment-before.json` 和 `deployment-after.json` 比较原 8 个案件、各案执行记录、9 条 ledger 和 261 行有效审计链。上线后另验 Grafana 同源只读 iframe、12 个面板查询、全屏和手机宽度，以及 4 个 Prometheus 目标。Trivy 使用 `--ignore-unfixed`，实际发布镜像的可修复 HIGH/CRITICAL 为 0，发布镜像 ID 与扫描一致。

本批次证明自有数据库中的人工恢复事务与 Worker 工具效果隔离，不代表外部 ERP Saga、企业真实收益或云 HA/PITR。整项目的完整部署入口、其余 UI 状态和比赛材料对齐仍在复核清单中。
